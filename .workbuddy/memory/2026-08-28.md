## Knowly 本地全文索引 + 对外查询 API（/api/v1）落地

背景：用户反馈"归档保存到群晖 NAS 了，但查询巨慢、没有好用 API 供外部服务调用"。根因是「文件即数据库」：每次搜索 = 新建 SSH + `grep -rn` 全树扫描（internal/ssh/client.go Search），详情每次 `ReadFile` SSH 往返。

决策过程（AskUserQuestion 两轮）：
- 拓扑：原推荐在 NAS 起搜索服务 → 用户澄清 **NAS 是群晖、装不了服务且性能弱** → 改为 Mac 内嵌 Knowly 守护。
- 引擎：用户选 SQLite FTS5（零依赖）。实测环境可联网，采用 `modernc.org/sqlite`（纯 Go、无 cgo、含 FTS5）。

实现要点：
- 新包 `internal/index`：FTS5 trigram 分词（中文子串友好），`Indexer` 接口（Index/Search/GetByPath/AllTags/Count），库文件 `~/.knowly/index.db`。≥3 字符走 MATCH，1-2 字符走 LIKE 兜底。
- `ssh.Client` 注入 `SetIndexer`：`SyncItem`（文本，带 title/tags）与 `SyncPDF`（URL）成功落盘后自动增量入索引——零额外 SSH，散落改动收敛为一处。图片不入索引（无文本），/entry 回源兜底。
- `internal/web`：新增 `handlers_v1.go`（search/entry/tags/status/admin/backfill，Bearer token 鉴权，`api.token` 留空则信任 WireGuard 网络隔离）与 `backfill.go`（递归遍历 NAS 解析 frontmatter 回溯建索引，幂等，TryLock 防并发）。authMiddleware 对 `/api/v1/` 前缀豁免 Basic/session。
- `cmd/knowly/main.go`：打开 index.db 注入 client+webSrv；启动 15s 后若索引为空自动后台回溯。
- 配置：`config.APIConfig{Enabled *bool(默认启用), Token string}`。
- NAS 仍是唯一真源，索引可随时重建——契合「Keep Nas As Sanctuary」。

验证：`go vet ./...` 干净、全量测试通过（新增 index 单测 + web v1 冒烟测试）、二进制构建成功。中文"双螺旋"等搜索命中验证 OK。

遗留/提醒：
- 用户需在 Mac 上重新编译部署 knowly 并重启守护；config.json 可选加 `api.token`。
- 外部服务调用：`curl -H "Authorization: Bearer <t>" http://<mac-wg-ip>:8090/api/v1/search?q=关键词`；Mac 需保活（launchd KeepAlive / watchdog 模式）。
- FTS5 trigram 对 <3 字符查询走 LIKE 兜底（本地扫描，个人规模无感）。
- API 文档已写入 docs/API.md §5.2。
